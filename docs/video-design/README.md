# 영상 게시판 디자인 검증 — 2026-11-02

추가 수정: PC·태블릿에서도 한 행에 영상 한 개가 콘텐츠 영역의 전체 너비로 표시되도록 변경했습니다. 16:9 비율과 재생 동작은 유지합니다. 아래 썸네일 표시 크기 및 캡처는 이 추가 수정 전의 디자인 검증 기록입니다.

로컬 프로덕션 빌드의 `/videos`에서 검증했습니다. Sanity에 등록된 두 영상과 제목·커버 데이터는 수정하지 않았습니다.

## 변경 및 실측

| 항목 | 모바일 | 데스크톱 |
| --- | --- | --- |
| 검증 CSS 뷰포트 | 393×852, DPR 3 | 1440×1030, DPR 2 |
| 제목 아래→첫 카드 간격 | 기존 CSS 기준 128px → 실측 64px | 기존 CSS 기준 188px → 실측 96px |
| 헤더 하단 padding | 48px → 32px | 80px → 48px |
| 목록 상단 padding | 40px → 32px | 64px → 48px |
| 카드 안쪽 padding | 16px → 8px | 24px → 12px |
| 제목·첫 카드 왼쪽 위치 | 둘 다 16px | 둘 다 120px |
| 재생 원 지름 | 56px → 38px | 64px → 42px |
| 첫 썸네일 실제 표시 크기 | 343×약 193px | 358×약 201px |
| 첫 썸네일 실제 로드 크기 | 1280×720px | 1280×720px |

기존 제목→카드 간격은 삭제한 설명 문구의 margin 및 28px 줄 높이를 포함한 CSS 기준입니다. 변경 후 값은 브라우저의 `getBoundingClientRect`와 `getComputedStyle`로 확인했습니다. 태블릿에서는 헤더 하단·목록 상단 각각 40px, 카드 안쪽 10px를 적용했습니다.

상단에는 `VIDEOS`와 `포베베 영상`만 표시합니다. 카드의 얇은 1px 테두리와 기존 공통 카드의 18/22px 반경은 유지합니다. 영상 카드에만 compact padding을 적용하고 다른 카드의 기본 padding은 유지합니다. 재생 버튼은 아이보리 원과 짙은 초록 삼각형이며 썸네일 전체가 버튼입니다. 영상 제목은 썸네일 12px 아래, 원본 링크는 제목 6px 아래에 둡니다.

## 썸네일 선명도

| 등록 영상 ID | 기존 hqdefault | sddefault | maxresdefault |
| --- | --- | --- | --- |
| `eqwfytYwqT8` | 480×360, HTTP 200 | 640×480, HTTP 200 | 1280×720, HTTP 200 |
| `kDWxuz2pXMo` | 480×360, HTTP 200 | 640×480, HTTP 200 | 1280×720, HTTP 200 |

실제 이미지 파일의 크기를 확인했고, 브라우저에서도 `currentSrc`와 `naturalWidth`/`naturalHeight`가 고해상도 파일을 가리키는 것을 확인했습니다. 모바일 DPR 3에서 첫 이미지에 필요한 물리 픽셀 폭은 약 1029px, 데스크톱 DPR 2에서는 약 716px입니다. 기존 480px 파일의 확대 표시를 1280px 파일로 개선했습니다. [YouTube 공식 썸네일 문서](https://developers.google.com/youtube/v3/docs/thumbnails)에서도 원본에 따라 제공 크기가 다를 수 있다고 설명합니다.

첫 커버의 작은 글자 가장자리는 1280×720 원본을 직접 열어도 다소 부드럽게 보입니다. 원본 디자인·압축에서 오는 부분까지 복원하거나 별도 커버로 교체하지 않았습니다. 두 영상 모두 고해상도 파일을 제공하므로 현재 등록 영상에서 낮은 해상도 파일로 돌아갈 필요는 없습니다.

고해상도가 없는 다른 영상은 `maxresdefault → sddefault → 기존 hqdefault` 순서로 대체합니다. HTTP 오류뿐 아니라 HTTP 200으로 제공되는 작은 플레이스홀더도 감지합니다. 브라우저에서 이미지 오류 이벤트를 두 번 모의 발생시켜 실제 640×480 파일, 기존 480×360 파일로 차례로 전환되는 것을 확인했습니다. 새로고침으로 정상 고해상도 상태를 복구했습니다. 이 검사는 CMS 데이터에 영향을 주지 않습니다.

## 동작 및 검사 결과

- `npm run build`: 통과. 빌드 과정의 TypeScript 검사 통과.
- `npm run lint`: 통과.
- `node --test tests/*.test.mjs`: 기존 검사 포함 19개 통과.
- `git diff --check`: 통과.
- 초기 HTML: iframe 0개. 첫 썸네일은 eager/high priority, 나머지는 lazy로 로드합니다.
- 모바일 크기: 첫 썸네일 한 번 클릭 후 같은 카드에 실제 등록 영상이 재생됐습니다. Chrome 미디어 제어에서 **일시중지**와 진행 시간 **0:16**을 확인했습니다.
- 데스크톱: 첫 썸네일 한 번 클릭 후 같은 카드의 유튜브 iframe 및 오디오 재생 상태를 확인했습니다.
- 영상 전환: 두 번째 영상 선택 시 첫 플레이어가 제거되고 두 번째 등록 영상만 재생됐습니다.
- **YouTube에서 보기**: 데스크톱에서 클릭 시 새 탭의 주소가 `https://www.youtube.com/watch?v=eqwfytYwqT8`로 열리는 것을 확인했습니다. 두 카드의 원본 링크 ID가 각 영상 ID와 일치합니다.
- 모바일·데스크톱 모두 첫 화면에 첫 썸네일과 재생 버튼이 표시되고 버튼이 식별되는 것을 확인했습니다.

미확인 항목: 실제 iOS Safari·Android 기기의 터치 재생, 모바일에서 원본 링크의 실제 새 탭 전환, 모든 브라우저의 자동 재생 정책, 고해상도 미제공 영상에서의 실제 HTTP 장애. 이미지 오류의 대체 단계는 모의 오류 이벤트로 검증했습니다. 원본 YouTube 탭의 전체 로딩 완료와 원본 사이트 내 재생은 별도로 확인하지 않았습니다.
